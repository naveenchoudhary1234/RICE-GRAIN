# ByProduct2Protein

A Streamlit app for Hack the Fork 2026 ("Upcycling India's by-products for
alternative proteins"). It is a **diagnosis-first** tool: given a rice bran
lot and an observed taste defect, it ranks candidate causes against cited
evidence, names the one test that confirms each cause, and recommends a
process route with trade-offs — instead of jumping straight to a number.

Tabs:
- **Diagnosis** — lot intake, defect selection, ranked candidate causes
  (RB01–RB13 evidence), Route A/B recommendation, next-best-measurement,
  FFA threshold check, Safety & Regulatory panel, and an Explain button.
- **Cost** — low/base/high cost-per-kg range, a yield sensitivity chart, and
  a break-even price vs. imported pea isolate. All defaults are **assumed**.
- **Evidence** — the full RB01–RB13 table and the Tan et al. (2023) paper
  facts, each with its source link.
- **Demo model (synthetic data)** — the original XGBoost regressor, clearly
  marked as using synthetic training data and disconnected from the
  Diagnosis tab's recommendations.

## ⚠️ Data honesty rules

Every number in this app carries a badge: **published**, **measured**,
**assumed**, **synthetic**, or **needs_lab_test**. If a value has no source,
the app shows "Needs pilot data" instead of a number. See the legend at the
top of the app and the permanent Limitations box at the bottom.

- `data/rice_bran_evidence.json` — RB01–RB13 evidence table (verbatim from
  the hackathon brief's pasted text; do not add facts not present there).
- `data/paper_facts.json` — PF01–PF25 facts from Tan, B.L.; Norhaizan, M.E.;
  Chan, L.C. *Rice Bran: From Waste to Nutritious Food Ingredients*.
  Nutrients 2023, 15, 2503. https://doi.org/10.3390/nu15112503
- `data/known_gaps.json` — explicit list of what the paper does *not*
  contain (yield, purity, cost, taste-change data) — shown in the
  Limitations box.
- `data/byproducts.json` / `data/treatments.json` — general by-product
  profiles used by the Demo model tab; still **placeholder** values.
- `data/literature_data.csv` — **synthetic** training data for the Demo
  model tab only, generated by `scripts/generate_literature_data.py`. It
  does not feed the Diagnosis tab.

### Replacing with real data

1. **Byproducts / treatments**: edit the JSON files directly, keeping the
   same keys (`protein_pct`, `limiting_compounds`, `flavour_issue`,
   `price_per_kg` for by-products; `treatment`, `efficacy_pct`, `notes` per
   compound for treatments).
2. **Literature data**: replace `data/literature_data.csv` with real
   experimental/literature records using this schema:

   | column | meaning |
   |---|---|
   | `by_product` | must match a key in `byproducts.json` |
   | `treatment` | treatment name (ideally matching `treatments.json`) |
   | `temp` | process temperature (°C) |
   | `time` | process duration (min) |
   | `enzyme_dose` | enzyme dose (% w/w), 0 if not applicable |
   | `protein_before` | protein % before treatment |
   | `protein_after` | protein % after treatment |
   | `bitterness_before` | sensory bitterness score before (0–10) |
   | `bitterness_after` | sensory bitterness score after (0–10) |

   More rows and wider parameter coverage will materially improve the
   XGBoost model's predictions. The app retrains automatically on whatever
   CSV is present (cached via `st.cache_resource`/`st.cache_data`; restart
   the app or clear cache after replacing the file).

## Running the app

```bash
pip install -r requirements.txt
streamlit run app.py
```

## Explain button / Gemini API

The "Explain" button (Diagnosis tab) sends Google Gemini only the app's own
diagnosis + cost results as JSON, with a system instruction telling it to
use only the provided data, add no numbers or claims, and say what test is
needed for missing data. The response is shown with the RB-series source
IDs that were referenced. Get a free API key at
https://aistudio.google.com/app/apikey, then provide it either via:

- Environment variable: `GEMINI_API_KEY`
- Or paste it directly into the password field in the app (not stored)

Optionally set `GEMINI_MODEL` to override the default model
(`gemini-2.0-flash`).

If no key is provided, the app will show an error instead of failing
silently. **Never paste a real API key into chat, commit it to the repo, or
hardcode it in source — always use the environment variable or the app's
password field.**

## Cost model

The cost-per-kg-of-concentrate calculation is a simple additive model:

```
cost_per_kg_concentrate = (raw_material_price + energy + labour + capex_amortization) / (yield_% / 100)
```

All cost assumptions (yield %, energy/labour/capex per kg of raw material,
and the imported pea isolate benchmark price) are editable in the sidebar
and are themselves placeholder defaults — replace with your own plant
economics.

## Regenerating sample literature data

```bash
python scripts/generate_literature_data.py
```

This overwrites `data/literature_data.csv` with freshly generated synthetic
placeholder data (same schema, different random seed behavior is fixed via
`random.seed(42)` for reproducibility).
